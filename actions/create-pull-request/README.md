# Create Pull Request

Automatically creates or updates a pull request for changes made during a workflow run.

## Features

✅ **Auto-commit changes** in the working directory
✅ **Create or update PRs** intelligently
✅ **Customizable commit metadata** (author, committer, signoff)
✅ **Add labels, assignees, reviewers** automatically
✅ **Draft PR support**
✅ **Uses GitHub CLI** for reliable PR operations

## Usage

### Basic Example

```yaml
- name: Make some changes
  run: |
    echo "Updated at $(date)" > UPDATED.txt

- name: Create Pull Request
  uses: TRI-Actions/custom-actions/actions/create-pull-request@main
  with:
    title: "chore: Update timestamp"
    body: "Automated update from workflow"
    branch: "auto-update-timestamp"
```

### With Labels and Reviewers

```yaml
- name: Generate documentation
  run: npm run docs

- name: Create Pull Request
  uses: TRI-Actions/custom-actions/actions/create-pull-request@main
  with:
    title: "docs: Update generated documentation"
    body: |
      ## Changes
      - Updated API documentation
      - Regenerated from latest code

      Auto-generated by workflow.
    branch: "docs-update"
    labels: "documentation,automated"
    reviewers: "user1,user2"
    draft: true
```

### Complete Example with Outputs

```yaml
- name: Update dependencies
  run: npm update

- name: Create Pull Request
  id: pr
  uses: TRI-Actions/custom-actions/actions/create-pull-request@main
  with:
    title: "chore(deps): Update npm dependencies"
    body: "Automated dependency update"
    branch: "deps-update"
    commit-message: "Update npm dependencies"
    labels: "dependencies"
    signoff: true

- name: Comment on PR
  if: steps.pr.outputs.pull-request-operation == 'created'
  run: |
    echo "Created PR #${{ steps.pr.outputs.pull-request-number }}"
    echo "URL: ${{ steps.pr.outputs.pull-request-url }}"
```

### Selective File Staging

```yaml
- name: Format code
  run: npm run format

- name: Create Pull Request
  uses: TRI-Actions/custom-actions/actions/create-pull-request@main
  with:
    title: "style: Format code"
    add-paths: "src/ tests/"  # Only commit src and tests directories
    branch: "auto-format"
```

## Inputs

| Input | Description | Required | Default |
|-------|-------------|----------|---------|
| `title` | Pull request title | **Yes** | - |
| `token` | GitHub token with PR write permission | No | `${{ github.token }}` |
| `branch` | Branch name to create/update | No | `automated-changes` |
| `base` | Base branch for the PR | No | Repository default branch |
| `body` | Pull request description | No | `""` |
| `commit-message` | Commit message | No | Same as `title` |
| `labels` | Labels to add (comma-separated) | No | `""` |
| `assignees` | Assignees (comma-separated usernames) | No | `""` |
| `reviewers` | Reviewers (comma-separated usernames) | No | `""` |
| `draft` | Create as draft PR | No | `false` |
| `delete-branch` | Delete branch when PR closed/merged | No | `false` |
| `add-paths` | Paths to stage (space-separated) | No | `.` (all changes) |
| `author` | Commit author (name <email>) | No | `${{ github.actor }}` |
| `committer` | Commit committer (name <email>) | No | `github-actions[bot]` |
| `signoff` | Add Signed-off-by line | No | `false` |
| `update-strategy` | How to update an existing remote branch: `replace` (reset branch to new commit and force-push) or `append` (cherry-pick new commit onto existing branch) | No | `replace` |

## Outputs

| Output | Description |
|--------|-------------|
| `pull-request-number` | PR number (e.g., `42`) |
| `pull-request-url` | Full PR URL |
| `pull-request-operation` | Operation performed: `created`, `updated`, or `none` |
| `pull-request-head-sha` | Head commit SHA |

## Behavior

### Creating vs Updating PRs

The action intelligently handles PR lifecycle:

1. **No changes detected**: Exits without creating PR (`operation: none`)
2. **Changes + No existing PR**: Creates new PR (`operation: created`)
3. **Changes + PR exists**: Updates existing PR (`operation: updated`)

The action checks for existing PRs by comparing `branch` and `base` names.

### Change Detection

The action commits:
- Modified tracked files
- New untracked files
- Staged changes

It respects `.gitignore` and only commits files matching `add-paths`.

## Common Use Cases

### 1. Automated Dependency Updates

```yaml
name: Update Dependencies
on:
  schedule:
    - cron: '0 0 * * 1'  # Weekly

jobs:
  update:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Update dependencies
        run: npm update
      - uses: TRI-Actions/custom-actions/actions/create-pull-request@main

          branch: "deps/weekly-update"
          labels: "dependencies"
```

## Permissions

The workflow needs these permissions:

```yaml
permissions:
  contents: write       # To push commits
  pull-requests: write  # To create/update PRs
```

### Using a PAT

For triggering other workflows on PR creation, use a PAT:

```yaml
- uses: TRI-Actions/custom-actions/actions/create-pull-request@main
  with:
    token: ${{ secrets.PAT }}
    title: "Update files"
```

Note: The default `GITHUB_TOKEN` doesn't trigger workflows on PRs it creates (to prevent infinite loops).

## Branch Strategy

### Fixed Branch Name (Default)

```yaml
branch: "automated-updates"
```

Pros: Updates same PR on every run
Cons: Multiple updates collapse into one PR

### Dynamic Branch Names

```yaml
branch: "update-${{ github.run_id }}"
```

Pros: Creates separate PR for each run
Cons: Can create many PRs

### Update Strategy for Existing Branches

When the target `branch` already exists on the remote, `update-strategy` controls
how it is updated:

- **`replace`** (default): The branch is reset to the newly created commit and
  force-pushed, overwriting the previous remote branch. Use this for branches
  that are regenerated on every run (e.g. dependency upgrades) — stacking commits
  there causes cherry-pick conflicts.
- **`append`**: The new commit is cherry-picked onto the existing remote branch,
  preserving prior commits. This can fail with a merge conflict if the branch has
  diverged from the base.

```yaml
- uses: TRI-Actions/custom-actions/actions/create-pull-request@main
  with:
    title: "chore(deps): upgrade dependencies"
    branch: "github-actions/upgrade-main"
    update-strategy: "replace"
```

### Date-based Branches

```yaml
- name: Create Pull Request
  env:
    DATE: ${{ github.event.repository.updated_at }}
  uses: TRI-Actions/custom-actions/actions/create-pull-request@main
  with:
    branch: "auto-update-$(date +%Y%m%d)"
    title: "Daily update"
```

## Troubleshooting

### No PR Created

**Check:**
- Are there actually file changes?
- Do you have `contents: write` permission?
- Is `add-paths` excluding your changes?

**Debug:**
```yaml
- name: Show git status
  run: git status
```

### PR Not Updating

The action updates PRs based on `branch` + `base` match. If you change branch names, it creates a new PR.

### Permission Denied

Ensure workflow has required permissions:
```yaml
permissions:
  contents: write
  pull-requests: write
```

### Commit Attribution Wrong

Customize with `author` and `committer`:
```yaml
with:
  author: "Bot <bot@example.com>"
  committer: "CI <ci@example.com>"
```

## Migration from peter-evans/create-pull-request

Most inputs are compatible:

```yaml
# Before
- uses: peter-evans/create-pull-request@v7
  with:
    branch: my-branch
    title: My PR

# After
- uses: TRI-Actions/custom-actions/actions/create-pull-request@main
  with:
    branch: my-branch
    title: My PR
```

**Key differences:**
- Uses `gh` CLI instead of REST API
- Simpler branch strategy (no suffix generation)
- No `branch-suffix`, `path`, or `body-path` support yet
